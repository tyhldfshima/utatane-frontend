> ③も歌手がコラボレーションやそこに演奏者まで加わるなどバリエーションが多数と、その際に全員のアカウントに自分のチャンネルで表示されるなど、多数を検討が必要

## 2. 用語の正本

★内部は木ではなく網（Version Graph）。1つの Version が複数の元を参照できる。

| 言葉 | 何であるか（1行） | 何でないか（1行） |
|---|---|---|
| 種（Seed） | 元を1つも持たない Version。音（伴奏・鼻歌・ビート・コード進行）でも詞でも譜面でもよい | 別の箱・別の表ではない。「曲」「詞」の2種類に限らない |
| Version | 網の1点。聴ける／読める1つの形（中身）と、参加者の一覧と、元への参照を持つ。★1つしか存在しない | 人ごとのコピーではない。「曲×詞」の固定の組ではない。完成品だけを指さない（伴奏だけ・詞だけも Version） |
| 派生元（Source） | Version から Version への矢印。「何を受け継いだか（詞・旋律・伴奏音源・編曲・歌唱音源 …）」を種類として持つ。1つの Version は0〜複数の元を持つ | 親は1人ではない。作品（家系）を指すのではなく、特定の Version を指す |
| 組み合わせ | 2つ以上の元を持つ Version のこと（例：詞A＋曲C＋アレンジD） | 特別な種類の Version ではない。元の数が2以上というだけ |
| 作品（家系） | ある Version から上流・下流に辿れる Version の集まりを、1つの歌として見せる窓 | データの親ではない。組み合わせの Version は2つ以上の家系に同時に属する |
| 参加者（Participant） | Version と人の関係1本。状態（招待中・承認待ち・参加・辞退・抜けた）を持つ | 人の属性ではない。「作曲家」という肩書きではない |
| 役割（Role） | 貢献の種類の一覧（作詞・作曲・編曲・歌唱・ギター・ベース・ドラム・ピアノ・MIX・映像・プロデュース …）。後から増やせる | 固定の列ではない。役割ごとに割合が決まっていない（「編曲は常に○%」としない） |
| 貢献（Contribution） | 参加者が、その Version で果たした役割1つ（1人が複数持てる）と、その説明（どの部分か） | 割合そのものではない。割合は Revenue Rule が持つ |
| 系譜の関係（上流関係） | 元の Version に貢献した人が、そこから生まれた下流の全 Version と持ち続ける関係。矢印を辿って求める | 下流の Version に参加者として書き写されるものではない |
| Revenue Rule | 「どの範囲（作品／Version）の、どの収益種別を、いつから、誰にどう分けるか」の取り決め1件。版を持ち、承認されて確定する | 全体で1つの固定比率ではない。過去に遡って書き換わらない |
| 同意の記録（Consent） | 誰が・いつ・何に（参加・役割・割合・公開・派生許可・外部転載・取り下げ）同意したかの、消さない記録 | 画面上のチェック状態ではない。上書きしない |
| チャンネル | 人ごとの表示面。その人と Version の関係（主催・参加・募集・応援）から並べる | Version を複製して置く場所ではない |
| 主催者（Host） | その Version を作って公開手続きを進める人（参加者の1人） | 所有者ではない。割合を1人で決めない |
| TYP | ありがとうを届けるポイント。「TYP を贈る」 | 「投げ銭」ではない |

### 2-1. 網の形（文章で）

★追補1・追補2で修正：矢印は Version 同士ではなく「Version が貢献を参照する」形（追補1 18章）。貢献と素材ファイルは分けて持つ。由来は全世代たどれる（追補2 27章）。以下は本編時点の記述として残す。

- Version は「中身」「参加者と貢献」「元への矢印（0〜複数）」「公開状態」を持つ。
- 矢印には「受け継いだもの」の種類を付ける：詞／旋律／伴奏音源／編曲／歌唱音源／映像／コード進行／リズム／翻訳 …（増やせる）。
- 「中身を物理的に含む」（伴奏音源や歌声をそのまま使う）矢印と、「着想・素材として使う」（詞を別の曲で歌う、旋律を編曲し直す）矢印を区別する。取り下げの影響（9章）で使う。
- 作品ページ＝ある種から下流を見る窓。Version ページ＝その Version と、上流（元）・下流（派生）を見る窓。

## 3. 45 ケースを通した表

書き方：各ケースで「種 → 派生・組み合わせ → 参加者（貢献） → チャンネル表示 → 権利（関係） → 収益 → TYP → さらに派生」を通し、最後に判定を書く。
判定：○＝この仕様で通る／△＝通るが要判断あり（15章の番号）／×＝いまの実装では表せない（理由）。
表記：V＝Version。「上流枠」「当V枠」は 6章の二段の分け方。

### A. 種と基本の組み合わせ

**ケース1　伴奏→詞がつく→歌われる（MVP の1本）**
- 種：Aさんが伴奏 V1 を置く
- 派生・組み合わせ：Bさんが V1 に詞を付けた V2（元＝V1：伴奏音源を含む）。Cさんが V2 を歌った V3（元＝V2：伴奏音源＋詞を含む）
- 参加者：V1＝A（作曲・編曲）／V2＝B（作詞）、主催B／V3＝C（歌唱）、主催C
- チャンネル：A は V1 を「自分の作品」、V2・V3 は「自分の歌から生まれた」として作品ページで見える。B は V2 を「自分の作品」、V3 を派生として。C は V3 を「自分の作品」
- 権利：A は V1 と、その下流の V2・V3 に上流関係。B は V2 と V3 に上流関係
- 収益：V3 の収益 → 当V枠（C）＋上流枠（V2 の Rule へ → B と、さらに V1 の Rule へ → A）
- TYP：V3 に贈られた TYP は V3 の Rule（TYP 種別）で分ける。A・B・C それぞれに「V3 から届いた」と表示
- さらに派生：D が V3 をピアノで再編曲 → V4（元＝V3）
- 判定：○（いまの実装は V2「詞だけ」を Version として持てないため × の部分あり：詞は Work で、Version は曲×詞×歌唱の完成形のみ）

**ケース2　詞→曲がつく**
- 種：B が詞 V1
- 派生：A が V1 に旋律と伴奏を付けた V2（元＝V1：詞）
- 参加者：V1＝B（作詞）／V2＝A（作曲・編曲）、主催A
- チャンネル：B「自分の作品」に V1、作品ページで V2。A「自分の作品」に V2
- 権利：B は V1・V2 とその下流。A は V2 とその下流
- 収益：V2 の収益＝当V枠（A）＋上流枠（V1 → B）
- TYP：V2 宛ては V2 の Rule で A・B に
- さらに派生：C が V2 を歌う（ケース1と同じ流れ）
- 判定：○

**ケース3　鼻歌→曲→詞→編曲**
- 種：E が鼻歌の録音 V1

## 4. チャンネル

### 4-1. 原則

- 1つの Version は、参加した全員のチャンネルに出る。データを人数分コピーしない（Version は1つ・関係が複数）。
- 再生数・いいね・TYP・コメントは同じ Version に集まる。どのチャンネルから再生・TYP を贈っても、同じ Version の数字が増える。
- どのチャンネルから来たかは「経路」として記録する（誰の紹介で聴かれたかを本人に見せるため。いまの `?ref=` の考えに近い：versions/[id]:19）。

### 4-2. 並び（上から）

1. 自分の作品：自分が主催した Version、自分が置いた種
2. 参加した作品：主催ではないが参加者として承認された Version
3. 自分の歌から生まれた：自分が上流関係を持つ下流の Version（多いので「最近」「よく聴かれている」で絞る）
4. 募集中：自分が出している募集（10章）
5. 応援：自分が TYP を贈った Version・人（本人が公開を選んだ場合だけ）

### 4-3. 表示の決まり

- 同じ Version が自分の作品と参加した作品の両方に当たるときは、上の方に1回だけ出す。
- 抜けた・匿名を選んだ参加者のチャンネルには出さない。
- 非公開の Version は参加者本人にだけ見える。

## 5. 貢献の種類（役割）

- 役割は一覧（増やせる表）で持つ。初期：作詞・作曲・編曲・歌唱・コーラス・ラップ・ギター・ベース・ドラム・ピアノ・キーボード・ストリングス・管楽器・打ち込み・ビート制作・MIX・マスタリング・映像・プロデュース・訳詞・その他（自由記述）。
- 1人が1つの Version で複数の役割を持てる（参加者1本に貢献が複数）。
- 役割に割合を結び付けない。「編曲は常に○%」とは決めない。役割ごとの「提案の既定値」を画面に出すかは要判断（15-10）。
- 役割は画面の色・アイコンの分類（言葉・音・演奏・仕上げ・映像）に束ねて表示してよい。束ね方は表示だけの話でデータを縛らない。

## 6. 権利と収益を分けて書く

### 6-1. 二つの関係

- 系譜の関係（元の作品に対する関係）：ある Version に貢献した人は、その Version から矢印で辿れる全ての下流 Version と関係を持ち続ける。原曲の作詞・作曲は、そこから生まれた全 Version と関係を持つ。Version 7 だけを編曲した人は Version 7 とその下流だけに関係する。
- その場の貢献（その Version に対する貢献）：その Version の参加者と貢献。

### 6-2. 収益の二段の分け方（提案）

★この節は置き換え済み（追補1 18-2 → 追補2 26-1）。確定：由来は全世代たどれる形で持ち、「どこまで・何回数えて」報酬を届けるかはデータの形に埋め込まず、その Version に適用された Revenue Rule が決める。以下は本編時点の記述として残す。

- 1つの Version の収益は、Revenue Rule で「上流枠」と「当V枠」（と、PF の取り分）に分ける。
- 当V枠：その Version の参加者で分ける。
- 上流枠：元の Version に渡す。元が複数なら元ごとに分ける（15-7）。渡された元は、自分の Rule で更に「自分の当V枠」と「自分の上流枠」に分ける。これを種まで繰り返す。
- 矢印の種類で、元の中のどの貢献に流すかを絞る（例：詞だけ受け継いだなら、元の中の作詞の貢献だけに流す）（15-5）。
- 20/20/30/5/25 は「仕様候補」＝初期テンプレートの1つとして残す（例：単純な「伴奏→詞→歌」の3人を、作曲20・作詞20・歌唱30・PF25・視聴5 に当てる）。DB に固定しない。

## 7. 分け前の決め方（Revenue Rule）

| 問い | 提案 |
|---|---|
| 誰が決めるのか | 主催者が案を出す。受け取る人全員（その Version の参加者）が承認して確定。上流枠の大きさは、元の Version の「派生の条件」として元の側が決める（15-2） |
| いつ確定するのか | 公開の前。★確定した Rule が無い Version は公開できない |
| 全員の承認が要るのか | 要る（割合を受け取る人全員）。承認しない人がいたら期限つきで止まる（ケース42） |
| 公開後に変えられるのか | 変えられる。新しい Rule を作り、全員が承認したら、適用開始日から有効 |
| 変えたとき過去の分は | 遡らない。過去の収益は、その時点で有効だった Rule の版で計算したまま |

Revenue Rule 1件が持つもの：
- 範囲：作品（家系）全体に対する既定か、特定の Version か
- 収益の種類：購入／TYP／定額の聴き放題の分配／広告／外部配信／視聴還元（第1実装なし）… 増やせる
- 適用開始日（と終了日）
- 上流枠・当V枠・PF の割合と、当V枠の中の人ごとの割合（または定額・無償）
- 版番号・状態（案・承認待ち・確定・失効）・承認の記録（8章）への参照

## 8. 同意の記録

- 何を記録するか：参加／役割／割合（Revenue Rule の版）／公開／派生の許可条件／外部への転載／取り下げ・辞退／匿名化。
- 1件に持つもの：誰が／いつ／どの Version・どの Rule の版に／何に（同意・拒否・撤回）／そのとき画面に出した文面（版番号と文面の要約値）／どこから（アプリ・ウェブ）。
- 記録は消さない・上書きしない。撤回も「撤回した」という新しい記録で残す。
- 本人がいつでも自分の同意の一覧を見られる。後から「聞いていない」と言われたときは、この記録と、そのとき出した文面の版を示す。
- 通知は記録と別。通知が届いたことは同意ではない。

## 9. 取り下げ・辞退・削除

| 場面 | 提案の扱い |
|---|---|
| 公開前に1人が抜ける | その人の貢献を外す。外せなければ公開しない。Rule は案に戻り再承認（ケース29） |
| 公開後に名前を外したい | 匿名表示にする。音源は残す。収益は受取継続か放棄を本人が選ぶ（ケース33①） |
| 公開後に音源ごと外したい | その Version は非公開にし、残りの人が作り直せるようにする（ケース33②） |
| Version 全体の取り下げ | 参加者全員の合意、または法的な求めで非公開。記録は保全（ケース34） |
| 種の作者が下流ごと止めたい | ★要判断（15-15）。提案：公開＝「すでに生まれた派生には取り消しが及ばない」派生許可を与えたことにし、新しい派生だけ止められる。ただし盗用・権利侵害・法的な求めは例外として下流も一時停止 |
| 下流への影響の決め方 | 矢印が「中身を物理的に含む」なら影響を受ける（止める候補）。「着想・素材として使う」なら影響しない |
| 表示 | 止まった元は「この元は公開を終了しました」と出し、系譜の線は残す（誰の歌から生まれたかは消さない） |
| 退会 | クレジットは「退会したユーザー」。収益は保留（15-16） |

## 10. 募集と参加の入口（4つ）

4. AI が候補を出す（将来）：役割・声域・ジャンル・過去の参加から候補を提示。提示だけで、参加は人の承認で決まる

## 11. TYP と収益の接点（A系統へ渡す条件）

画面で「誰に何が届いたか」が分かる形：
- TYP を贈った人：「あなたの 300 TYP は、この歌に関わった5人と、元の歌の2人に届きました」と内訳を見せる（名前・役割・量）
- 受け取った人：「V3（Cさんの歌）から 45 TYP が届きました。あなたの伴奏から生まれた歌です」と経路を見せる

A系統（中央のウォレット）に渡す条件（中身には踏み込まない）：
- 分配の確定1件ごとに：元になった出来事（購入・TYP・…）／Version／収益の種類／額／使った Revenue Rule の版／受取人ごとの額と経路（当V枠か、何世代上の上流枠か）／端数の扱い
- 受け取りを保留する人の印：承認前・退会・本人確認前・盗用申し立て中
- TYP の宛先の区別：Version 宛て（Rule で分ける）か人宛て（その人へ全部）か（15-1）
- 視聴還元の種類は予約だけして、第1実装では発生させない

## 13. UI の原則

- 管理画面のようにしない。表・設定の並びではなく、聴いている画面の中に次の一歩（TYP を贈る・歌ってみる・Version を投稿する）を置く。
- スマホとアプリが前提。片手で届く下側に主な操作。再生を止めずに参加の画面へ進める。
- 割合・同意は「読む → うなずく」の2手で終わる形。数字は円グラフより「この歌が100売れたら、あなたに○」の言い方で見せる。
- 系譜は「森」として見せる：種が根、Version が枝。網の合流（組み合わせ）は「2本の枝が1つの花になる」表現。
- 同じ Version が何人のチャンネルに出ても、見た目は同じカード。誰のチャンネルで見ているかで「あなたの役割」だけを差し替える。
- 「投げ銭」の言葉を使わない。TYP の額に ¥ を付けない。

## 14. 視聴者5%（仕様として残す・第1実装に入れない）
