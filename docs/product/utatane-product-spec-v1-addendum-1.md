## 16. えふさん確定（2026-09-18・原文のまま）

> Aさんが一人で、 詞A ＋ 曲A ＋ 編曲A ＋ 歌唱A を作ってVersion Aを公開したあと、 Bさん：詞A ＋ 新曲B Cさん：曲A ＋ 新詞C Dさん：詞A ＋ 曲A ＋ 新歌唱D Eさん：詞A ＋ 曲A ＋ 新編曲E ＋ 新歌唱E Fさん：新詞F ＋ 曲A ＋ 編曲G ＋ 歌唱H まで成立させます。 重要なのは、完成Versionを分解してコピーするのではなく、詞・曲・編曲・歌唱等のContributionを参照して新しい組み合わせを作ることです。 各Contribution単位で、本人が再利用条件を指定できる仕様にしてください。 例えばAさん自身が、詞A＝承認が必要／曲A＝自由にコラボ可／編曲A＝このVersionでの利用のみ／歌唱A＝派生利用不可 と設定できるようにする。 さらに再利用条件も、少なくとも自由に利用可／申請して承認後に利用可／利用不可を表現できる器にします。 ただし、投稿者が設定すれば法的な権利処理がすべて完了する、とは扱わないでください。原作品、共同著作、編曲、実演、録音物などは実際の権利関係を③/B系統で別途整理します。UI上の「再利用設定」と法的権利そのものを同一視しない設計にします。 Aさんが実際にB版へ参加している場合は参加作品。AさんのContributionから派生しただけなら派生作品です。 チャンネルは概念的に、自分の作品 / 参加作品 / 自分の作品から生まれた派生作品 / コラボ募集中 などを区別できる構造にします。 これも内部ではコピーせず、同一Versionと関係を表示するだけです。 さらにケースには、 一人で作詞＋作曲＋編曲＋歌唱 → 曲だけ再利用 → 新しい詞 → 新しい歌手 → さらに別人が編曲 → 元の詞だけ再び別曲へ のような3〜4世代の派生も最低数ケース入れます。 1世代だけ通っても、UTATANEの「森」が育ったときに破綻する可能性があるためです。 （utatane-backend について）最終構成ではRailwayの utatane-backend を廃止する方向で設計してよいです。ただし、廃止実行は件数確認・Stripe切替・中央API切替・必要データ処理が終わった後。つまり「将来も残すか未決定」ではなく、廃止方針、廃止時期だけ未確定とするのが正確です。 最終形は、UTATANE Web / iOS / Android → TYHLD-platform API → 中央DB・共通基盤＋UTATANE固有領域 です。

## 17. ★★法的な権利と切り離す（最初に明記）

**画面の「再利用の設定」は、UTATANE の中での運用上の許可（本人の意思表示）であって、法的な権利の処理が終わったことを意味しない。**

**投稿者が再利用の設定をしても、それだけで著作権・著作者人格権・著作隣接権などの権利処理が完了したとは扱わない。**

**原作品・共同著作・編曲（二次的著作物）・実演・録音物（原盤）の実際の権利関係は、③（B系統）で別途整理する。この文書はその結論を出さない。**

設計への反映：
- 再利用条件の記録と、権利関係の記録を別のものとして持つ。再利用条件の欄に「権利処理済み」を意味する値を置かない。
- 設定画面の文言は「この詞をほかの人が使うことについての、あなたの希望」とし、「許諾」「権利」の言葉を使わない（言葉の最終形は ③ の整理後に確定）。
- 貢献の種類に「性質」の印を付けておく（③の整理で使うための手掛かりで、判断ではない）：
  - 作品系：詞・曲（旋律）・編曲
  - 実演系：歌唱・各楽器の演奏
  - 録音系：音源（録音・MIX・マスタリングを経た音そのもの）
- ★注意：「伴奏」は1つの貢献に見えて、実際は「編曲（作品系）＋演奏（実演系）＋録音（録音系）」の束。本編の「伴奏音源」はこの束を1つとして扱っていた。再利用条件は束ではなく、それぞれに付けられる器にする（誰が付けるかは要判断 24-4）。
- ★追補2で確定（確定1）：「曲」はメロディ等の創作物と、それを利用するための素材（譜面・MIDI・ガイド音源など）を区別して持てる。歌唱・演奏も必要に応じて独立音源を持てる。貢献と素材ファイルの関係は追補2 27章の最小単位の表。

## 18. 貢献（Contribution）を単位にする — 本編の形の修正

### 18-1. 言葉の追加・修正

| 言葉 | 何であるか（1行） | 何でないか（1行） |
|---|---|---|
| 貢献（Contribution） | 詞・曲（旋律）・編曲・歌唱・演奏・MIX・映像などの1つ1つ。中身・作った人（1人以上）・生まれた Version・再利用条件を持つ | Version の中の1行の飾りではない。Version を分解したコピーではない |
| 生まれた Version | その貢献が最初に公開された Version。貢献ごとに1つだけ | 貢献の持ち主ではない。貢献が使われている全 Version のことではない |
| 参照 | 新しい Version が、既にある貢献を「そのまま使う」関係 | コピーではない。★参照は常に元の貢献そのものを指し、途中の Version の中の貢献を指すことはない（中間の Version は貢献を持っていないため） |
| 改変元 | ある貢献が別の貢献を手直しして生まれたときの、元の貢献への矢印（例：詞A の一部を書き換えた詞A′） | 参照ではない。改変元を持つ貢献は新しい貢献として、自分の再利用条件を持つ |
| 再利用条件 | 貢献ごとに、本人が付ける「ほかの Version で使うことへの希望」。版を持つ | 法的な許諾ではない（17章） |
| 参加 | ある Version で、新しい貢献を作った（その Version が貢献の生まれた Version である）こと | 自分の既存の貢献が使われただけのことではない |
| 派生 | ある Version が、別の Version で生まれた自分の貢献を参照していること（自分は新しい貢献をしていない） | 参加ではない |

### 18-2. 本編からの変更点

- 本編 2-1 では「派生元の矢印＝Version から Version」だった。これを「Version は貢献の集まりで、貢献は新しく作るか既存を参照するか」に改める。Version 同士の元・派生の関係は、参照している貢献の生まれた Version から求める（保存しない）。
- ★本編 6-2 の「上流枠を元の Version の Rule に渡して種まで繰り返す」は、貢献単位の再利用では破綻する（25章 ②）。例：Fさんの Version は曲A だけを使うのに、Version A の Rule に流すと、使っていない歌唱A・編曲A にまで流れる。**上流への分配は、参照している貢献（と、その改変元）の作者へ直接届く形に改める**（割合は決めない。直接届く形の中身は A系統と④）。
- ★追補2で修正（確定2）：改変元・基にした元の由来は「1代前まで」で止めず、全世代たどれる形で持つ。どの由来まで報酬の対象にするかはデータの形に入れず、その Version に適用された Revenue Rule が決める（追補2 26-1）。
- 本編ケース1〜45 は、この修正後も「矢印＝参照している貢献」と読み替えれば筋は変わらない。ケース4・5（詞だけ／旋律だけ受け継ぐ）の要判断 15-5 は、この修正で「参照した貢献の作者にだけ届く」として解ける。

## 19. 貢献ごとの再利用条件の器

### 19-1. 器（3つの軸）

| 軸 | 取れる値 | 説明 |
|---|---|---|
| ① 使えるか | 自由に使える／申請して承認を得れば使える／使えない | ★必須の3つ。★確定4：初期値は「申請して承認を得れば使える」。作者が自由・使えないへ変えられる |
| ② どこで | どの Version でも／この Version（と、その改訂）の中だけ／指定した人だけ | 「このVersionでの利用のみ」はここで表す |
| ③ 付帯の希望（将来） | 手を加えてよいか（そのまま使う／手直しもよい）／UTATANE の外へ出してよいか／販売してよいか | 第1実装は持たなくてよい。器の枠だけ用意 |

- クレジット（名前の表示）は条件ではなく、常に必ず出す（本人が匿名を選んだ場合を除く：本編9章）。
- 条件は「版」を持つ。変えるたびに新しい版を作り、古い版を消さない。

### 19-2. えふさん例の表し方

| 貢献 | ① 使えるか | ② どこで | 新しい Version から見た結果 |
|---|---|---|---|
| 詞A | 申請して承認を得れば使える | どの Version でも | A に申請 → 承認で使える |
| 曲A | 自由に使える | どの Version でも | 申請なしで使える |
| 編曲A | 使えない（新しい Version では） | この Version の中だけ | 新しい Version では使えない。Version A の改訂（本編15-11 を認めた場合）や、投稿しないカラオケ再生では使える |
| 歌唱A | 使えない | — | どこでも再利用できない |

★「このVersionでの利用のみ」と「使えない」の違い：新しい Version から見るとどちらも使えない。違いは「Version A 自身の改訂・投稿を伴わない再生（カラオケ）」で使えるかどうか。

### 19-3. 共作の貢献の条件

- 詞を2人で書いた場合、貢献は1つ・作者は2人。
- ~~推し：合意できなければ「より厳しい方」を採る~~ → ★確定5（追補2で修正）：「厳しい方を自動で採る」はやめる。**全権利者の必要な同意が揃わなければ使えない**を基本にする。
  - 各作者が自分の希望（自由／承認／使えない）を持つ。「自由」を選んだ作者は、その時点で同意を与えたことになる。「承認」の作者には申請が届き、その人の承認が要る。1人でも「使えない」なら使えない。
  - 全員の同意がそろったときだけ使える。そろわない・返事が無いときは使えない（自動では決めない）。
  - 共作のときに「再利用の申請はこの人が代表して返事する」と前もって全員が同意しておく形を持てる（代表の返事＝全員の必要な同意。追補2 ケース62）。
  - ★追補3 #3：承認方式は「全員承認」か「代表者へ承認権限を委任（全員が事前に委任）」を基本にする。アカウント状態と権利状態は別で、退会・死亡で権利は消えない（追補3 35章）。

## 20. 条件は後から変えられるか

### 20-1. 推し

**変えられる。変えた後の条件は、これから始まる新しい利用だけに効く。すでに生まれた派生はそのまま残す。**

理由：
1. 派生した人は、そのときの条件を信じて自分の時間と才能を注いでいる。後から消えると、UTATANE の土台（安心して一緒に作れる）が崩れる。
2. 1人の変更で、他人の作品が一斉に消えると、森が育つほど1つの変更の被害が大きくなる（ケース35の構造と同じ）。
3. 利用した時点の条件の版を記録しておけば、「いつ、どの条件で使ったか」を示せる（21章の記録）。
4. 例外（法的な求め・盗用の申し立て）は本編9章の手続きで個別に止める。条件の変更とは別の道にする。

### 20-2. 細かい決めごと

| 場面 | 推し |
|---|---|
| 公開済みの派生 | そのまま。利用時の条件の版を記録に残す |
| 厳しくした（自由→承認、承認→使えない） | 以後の新しい利用に効く |
| 緩めた（承認→自由） | 承認待ちの申請は、申請不要になったとして進める |
| 下書き中（参照はしたが未公開）の派生 | ★確定7：最終判定は公開時。途中で条件が変わったら下書き中の人に通知し、公開の条件を公開時に再検証する |
| 承認済みで未公開の派生 | ~~承認は有効のまま~~ → ~~新しい条件が「使えない」なら通らない~~ → ★追補3 #1：①貢献の現在の再利用ポリシー ②個別に成立した Permission/Consent ③公開時の再検証の結果 を別々に持つ。ポリシーの変更で②が失効するかは許諾ルールの項目として明示する。初期の商品ルールは「公開時点で有効な許諾が必須」（追補3 33章） |
| 条件を変えたことの記録 | 変更も同意の記録と同じく、消さない記録にする（誰が・いつ・どの版からどの版へ） |

## 21. 申請して承認を得る流れ

### 21-1. 流れ

1. 使いたい人が、下書きの Version で貢献を選ぶ。条件が「承認」なら、その場で「申請する」に切り替わる（画面で先に分かる。作り終わってから断られない）。
2. 申請に添えるもの：どの貢献を／どんな Version で（下書きの試聴・詞・参加者）／ひとこと。
3. 届く先：その貢献の作者（共作なら全員）。通知と、作者のチャンネルの「届いた申請」。
4. 作者の返事：承認／見送り／質問を返す。承認は「その下書き1つ」に対して与える（ほかの Version へは使い回せない）。
5. 返事が無いとき：期限（長さは要判断 24-7）を過ぎたら「承認されなかった」として閉じる。★自動承認にはしない。申請した人は、別の貢献に差し替えるか、もう一度申請できる。
6. 見送られたとき：申請した人にだけ「今回は見送られました」と出す。理由は任意。★見送りは他の人に見えない。見送りの回数も公開しない。
7. 承認されたら：下書きに戻り、ほかの承認・参加者の承認・Revenue Rule の確定（本編7章）がそろえば公開できる。

### 21-2. 承認の記録（本編8章の同意の記録に足す）

- 種類：再利用の申請／承認／見送り／期限切れ／取り消し
- 持つもの：申請番号／対象の貢献／そのときの条件の版／使う先の下書き Version／申請した人／返事をした人（共作なら1人ずつ）／いつ／返事の内容／添えた文面／そのとき画面に出した説明文の版
- 消さない・上書きしない。取り消しも新しい記録。
- 公開された Version には「どの貢献を・どの条件の版で・誰の承認で使ったか」が必ず辿れる。

## 22. チャンネル — 参加と派生を分ける

### 22-1. 種別（本編 4-2 を置き換え）

人 P と Version V の関係を、次の順に1つだけ決める（上に当たったら下は見ない）。データはコピーせず、同じ V と関係を出すだけ。

| 順 | 種別 | 決め方 |
|---|---|---|
| 1 | 自分の作品 | P が V の主催者 |
| 2 | 参加作品 | P が V で新しい貢献を作った（V が P の貢献の生まれた Version） |
| 3 | 自分の作品から生まれた派生作品（★確定6：「自分の貢献が使われた作品」として表す） | V が、ほかの Version で生まれた P の貢献（詞・曲・編曲・歌唱・演奏・音源…どれでも）を参照している。P は V で新しい貢献をしていない |
| — | コラボ募集中 | Version ではなく、P が出している募集（本編10章） |
| — | 応援 | P が TYP を贈った Version（本人が公開を選んだとき） |

- 自分の作品・参加作品・派生作品に同時に当たっても、表示は1回（上の種別）。
- ★Aさんが B版で新しい貢献（例：コーラス）をすれば参加作品。Aさんの詞A が使われただけなら派生作品（えふさん確定どおり）。

### 22-2. 派生作品の見え方

| 決めごと | 推し |
|---|---|
| 言葉 | 見出しは「あなたの詞から生まれた歌」「あなたの曲から生まれた歌」のように、貢献の種類で言う。カードには「詞を使った作品」と付け、★「参加」「共演」「feat.」の言葉を使わない |
| 数の見せ方 | 「この詞から生まれた歌 12」。内訳は「直接 8・その先から 4」（その先＝改変元を通して、など間接のもの） |
| 並び | 既定は新しい順。切替で「よく聴かれている順」。自分がフォローしている人の作品を上に |
| 非表示 | 本人が自分のチャンネルで個別に非表示にできる。★非表示はチャンネルの見た目だけで、関係（クレジット・分配・系譜）は消えない。相手の Version 側のクレジットは消せない（消したいときは本編9章の手続き） |
| 自分の声・演奏が使われた場合 | ~~歌唱・演奏だけ「あなたの歌声が使われた作品」と分けて出す~~ → ★確定6（一般化）：歌唱だけ専用にせず、「あなたの貢献が使われた作品」として、詞・曲・編曲・歌唱・演奏すべてを同じ形で表す。カードには使われた貢献の種類（「詞が使われた」「歌声が使われた」「ギターが使われた」…）を出す |
| Version 側の表示 | V のページでは、参加者（この Version で作った人）と「使われた貢献」（ほかの Version から来たもの、元の Version へのリンクつき）を別の段で出す |

## 23. 追加ケース（46〜60）

書き方：本編と同じく、種 → 派生・組み合わせ → 参加者（貢献） → チャンネル表示 → 権利（関係） → 収益 → TYP → さらに派生 → 判定。さらに「誰のチャンネルに・参加として・派生として出るか」を必ず書く。
Aさんの条件（46〜54 共通）：詞A＝承認／曲A＝自由／編曲A＝このVersionのみ／歌唱A＝使えない。
判定：○通る／△要判断（24章の番号）／止まる（仕様どおり途中で止まる）／破綻（この仕様のままでは成り立たない）。

### F. えふさん確定の5つの形

**ケース46　Bさん：詞A＋新曲B**
- 種：Version A（A：詞A・曲A・編曲A・歌唱A）
- 組み合わせ：Version B＝詞A（参照）＋曲B（新・B）。音を出すには曲B側の伴奏または仮歌が要る（B が作れば編曲B・歌唱B も B の新しい貢献）
- 手続き：詞A は承認制 → A に申請 → 承認 → 公開
- 参加者：B（主催・作曲 ほか）
- チャンネル：B＝自分の作品。A＝派生作品（「あなたの詞から生まれた歌」）
- 権利：A は詞A の作者として Version B と関係。曲B は B の新しい貢献で、B が再利用条件を付ける
- 収益：Version B の収益から、参照した詞A の作者 A と、B に届く（割合は決めない）
- TYP：Version B 宛ては同じ流れ。A にも「Version B から届いた」と表示
- さらに派生：曲B を使う人（B の条件による）、詞A を使う人（A の承認）
- 判定：○
- 変形：A が承認のついでに Version B でコーラスを録る → A は参加作品（新しい貢献「コーラス」を作ったため）

**ケース47　Cさん：曲A＋新詞C**
- 組み合わせ：Version C＝曲A（参照・自由）＋詞C（新・C）
- 手続き：申請不要
- ★伴奏：曲A は旋律（作品系）。編曲A（伴奏の編曲）は「このVersionのみ」で使えない。★Version C で音を出すには、C が伴奏を用意するか、旋律だけの仮の音（曲A の中身として旋律の音があれば）で出すかのどちらか
- 参加者：C
- チャンネル：C＝自分の作品。A＝派生作品（「あなたの曲から生まれた歌」）
- 収益・TYP：Version C → C と、曲A の作者 A
- 判定：△（24-3 曲の貢献の「中身」に何を含むか：譜面だけ／旋律の音も／伴奏も。含めるものによって C が何を用意すべきかが変わる）

**ケース48　Dさん：詞A＋曲A＋新歌唱D**
- 組み合わせ：Version D＝詞A（承認）＋曲A（自由）＋歌唱D（新）
- ★伴奏が決まっていない：歌唱は伴奏の上で録るのが普通。Version A の伴奏（編曲A＋演奏＋録音）は「このVersionのみ」で使えない。★D がアカペラで歌う・自分で伴奏を作る（新しい貢献）・別の人の伴奏を参照する、のどれかにしないと成立しない
- 手続き：詞A の申請 → 承認
- 参加者：D（主催・歌唱。伴奏を作れば編曲・演奏も）
- チャンネル：D＝自分の作品。A＝派生作品（詞と曲が使われた）
- 判定：止まる（伴奏の出どころを選ばせる画面が要る）。★えふさんの5つの形のうち、Aさんの例の条件のままでは D はそのままでは成立しない、が発見

**ケース49　Eさん：詞A＋曲A＋新編曲E＋新歌唱E**
- 組み合わせ：Version E＝詞A（承認）＋曲A（自由）＋編曲E（新）＋歌唱E（新）。伴奏は E が作るので、ケース48の問題は起きない
- 手続き：詞A の申請 → 承認
- 参加者：E
- チャンネル：E＝自分の作品。A＝派生作品
- 収益・TYP：E と、詞A・曲A の作者 A
- さらに派生：編曲E は E が条件を付ける。自由にすれば、次の人が「詞A＋曲A＋編曲E＋新歌唱」を作れる（ケース48の解決の道にもなる）
- 判定：○

**ケース50　Fさん：新詞F＋曲A＋編曲G＋歌唱H**
- 組み合わせ：Version F＝詞F（新・F）＋曲A（参照・自由）＋編曲G（新・G）＋歌唱H（新・H）
- 手続き：申請不要（参照は曲A だけで、自由）。G・H の参加の承認と Revenue Rule の承認は要る（本編7章）
- 参加者：F（主催・作詞）、G（編曲）、H（歌唱）
- チャンネル：F＝自分の作品。G・H＝参加作品。A＝派生作品（曲だけ）
- 権利：A は曲A を通してだけ関係。詞A・編曲A・歌唱A は使われていない
- 収益：F・G・H と、曲A の作者 A。★本編6-2 のままだと Version A の Rule 全体に流れ、使われていない歌唱A・編曲A にも届いてしまう → 18-2 の修正で解く
- 判定：○（本編の形のままなら破綻。修正後は通る）

### G. 3〜4世代の派生

**ケース51　1人で全部 → 曲だけ再利用 → 新しい詞 → 新しい歌手 → 別人が編曲 → 元の詞だけ再び別曲へ（4世代）**
- 第0世代：Version A（A：詞A・曲A・編曲A・歌唱A）
- 第1世代：Version J＝曲A（参照・自由）＋詞J（新・J）。仮歌 J（新・J：歌唱）。伴奏なし（旋律と仮歌）
- 第2世代：Version K＝詞J（参照）＋曲A（参照）＋歌唱K（新・K）＋ギター弾き語り（新・K：演奏）。詞J の条件は J が付けたもの（ここでは自由とする）
- 第3世代：Version L＝詞J（参照）＋曲A（参照）＋歌唱K（参照）＋編曲L（新・L）＋ストリングス演奏（新・L）。★K の歌声を使うので、歌唱K の条件による（ここでは K が「承認」→ K が承認）
- 第4世代：Version M＝詞A（参照・承認）＋曲M（新・M）＋歌唱M（新・M）。元の詞だけが別の曲へ戻る
- チャンネル：

| 人 | 自分の作品 | 参加作品 | 派生作品 |
|---|---|---|---|
| A | Version A | — | J・K・L（曲A）、M（詞A） |
| J | Version J | — | K・L（詞J） |
| K | Version K | — | L（★「あなたの歌声が使われた作品」） |
| L | Version L | — | — |
| M | Version M | — | — |

- 権利：どの世代でも、参照は元の貢献を指す。L は第0世代の曲A を直接参照している（K を経由しない）ので、A との関係は世代が進んでも切れない
- 収益：Version L の収益は、L と、参照した詞J（J）・曲A（A）・歌唱K（K）の作者に届く。★K の弾き語りのギター（K の演奏）は L で使われていないので届かない
- TYP：Version L 宛ては同じ流れ。A の画面には「曲A → Version J → K → L」の経路ではなく、「曲A が Version L で使われた」と出す（経路は Version L のページで辿れる）
- さらに派生：編曲L を使う人が出れば第5世代
- 判定：○（25章の4点すべて通る）

**ケース52　世代をまたいだ手直し（改変元の連鎖）と二重数え**
- 第0世代：Version A
- 第1世代：Version N＝曲A（参照）を N が手直しした曲A′（新・N、改変元＝曲A）＋詞N（新）
- 第2世代：Version P＝曲A（参照）＋曲A′（参照：サビだけ A′ の旋律）＋詞P（新）
- 問題：A は「曲A を直接」と「曲A′ の改変元として」の2本の道で Version P と関係する
- チャンネル：A＝派生作品（1回だけ）。N＝派生作品
- 数：A の「この曲から生まれた歌」に Version P を2回数えない（Version の番号で重ねない）
- 収益：★曲A の作者 A に2回届くか？ 推し：同じ貢献（曲A）は1つの Version の中で1回だけ数える。改変元を通した関係は、直接の参照と同じ貢献なら重ねない
- 判定：△（24-9 改変元を通した関係に分配を届けるか・何代前まで）。★重ねないと決めない限り、ここは破綻する（二重に届く）
- ★追補2で修正：「同じ貢献は1回だけ」を2つに分ける。①貢献の一意性（系譜の重複除去）＝同じ貢献を1つの Version で何度参照しても、貢献は1つとして扱い、系譜・数には1回だけ出す（構造の決まり）。②報酬の計算の基礎＝「だから報酬も必ず1回」とは固定しない。道ごとに数えるか1回にまとめるかは Revenue Rule が決める（追補2 26-2）

### H. 条件が違う・途中で止まる・条件が変わる

**ケース53　貢献ごとに条件が違い、途中で止まる**
- 53-1：Q が「詞A＋曲A＋歌唱A（リミックス）」を作ろうとする → 歌唱A は使えない → ★選ぶ画面の時点で「使えない」と出て、下書きに入れられない（作ってから断られない）
- 53-2：R が「詞A＋新曲R」で申請 → A が見送り → R にだけ「今回は見送られました」。R は詞を差し替えるか、取りやめる
- 53-3：S が「詞A＋曲A＋新編曲S」で申請 → 期限まで返事なし → 「承認されなかった」で閉じる。S は再申請か差し替え
- 53-4：T が「詞A＋曲A＋編曲A＋新歌唱T」 → 編曲A は「このVersionのみ」で使えない → 画面で先に分かる → T は伴奏を作るか、ケース49の編曲E（自由なら）を選ぶ
- チャンネル：どれも公開されないので、誰のチャンネルにも出ない。申請と返事は同意の記録にだけ残る
- 判定：止まる（仕様どおり）

**ケース54　条件を後から変えた後に、新しい派生が来る**
- 経過：ケース47（Version C）とケース50（Version F）が公開された後、A が曲A を「自由 → 承認」に変える
- 既存：Version C・F はそのまま。記録には「曲A の条件 版1（自由）で利用」と残る
- 新規：U が曲A を使いたい → 版2（承認）なので申請が要る
- 下書き中：V が、変更の前に曲A を入れて下書きしていた → 通知「曲A の条件が変わりました。公開するには申請が要ります」（24-6）
- 逆向き：A が詞A を「承認 → 自由」に変えた → 承認待ちの申請は申請不要として進む
- チャンネル：A の派生作品に C・F は残る。U は承認されて公開されれば加わる
- 判定：△（24-6）

### I. 別々の元を組み合わせた Version から、さらに派生

- 破綻したもの：ケース50（本編の分配の形のまま）、ケース52（二重に届く）、ケース58（改訂による循環）。いずれも「決まりを1つ置けば解ける」形で、データの持ち方を貢献単位にすること自体は破綻しない。
