## 1. この文書の約束

- 言葉：TYP は「ありがとうを届けるポイント」。動詞は「贈る」「届く」。「送金」「支払い」「購入代金」の言葉を贈る場面に使わない。TYP の量に ¥ を付けない。
- ★未確定の空き枠：③で決まるものが入る場所は【③で確定】と書いた空き枠にする。空き枠は、③が決まるまで利用者の画面には出さない（出すのは設計の上だけ）。
- ★数字：この文書に出てくる数字はすべて【見本】。分配率・手数料・換算は見本でも書かない。えふさん確定の「100 TYP」も説明の見本として使う。
- スマホが先。PC の並びは各画面の最後に書く。
- 画面の数字（残高・届いた量・分配の結果）は、中央から受け取ったものをそのまま出す。★UTATANE の画面で計算しない（割合から量を出さない）。

## 3. A. Wallet TOP

### 3-1. 載せるもの（スマホ・上から順）

1. 見出し：「TYP」／右上に「？」（TYP とは：ありがとうを届けるポイント）
2. 残高カード
   - 大きく：「いま使える TYP」【見本：1,240 TYP】（中央の値をそのまま）
   - 小さく：「反映待ち ＋【見本：100】TYP」（中央で確定前のものがあるときだけ）
   - リンク：「内訳を見る」（7章の内訳シート）
   - ★円の換算は出さない。【③で確定：円での価値・受け取れる額の表示を入れるか】の空き枠
3. 主なボタン（横並び2つ）：「TYP を贈る」「届いた TYP」
   - 【③で確定：円での受け取り・出金】の空き枠（③の後に3つ目のボタンとして合流）
4. 「最近届いた TYP」3件（各行に「なぜ？」）→「すべて見る」で C へ
5. 「最近贈った TYP」3件（各行に状態：届きました／確かめています）→「すべて見る」で履歴へ
6. 「TYP でできること」短い説明（ありがとうを届ける・歌を育てる）。できることの一覧のうち③で決まる行は空き枠

### 3-2. 押せる所と行き先

| 押す所 | 行き先 |
|---|---|
| 「？」 | TYP の説明シート |
| 「内訳を見る」 | 内訳シート（7章） |
| 「TYP を贈る」 | B（相手を選ぶところから） |
| 「届いた TYP」／「すべて見る」 | C |
| 届いた行の「なぜ？」 | D |
| 贈った行 | 贈った記録の詳細（記録番号・相手・歌・状態） |

### 3-3. 言葉（文言案）

- 残高：「いま使える TYP」
- 反映待ち：「反映待ち（まもなく使えるようになります）」
- 空の時：「まだ TYP はありません。好きな歌に、ありがとうを届けてみませんか」
- 最近届いた：「〇〇さんから、『（歌の名前）』を通して届きました」

### 3-4. PC の並び

- 左の列：残高カード → 主なボタン → TYP でできること
- 右の列：タブ「届いた」「贈った」で履歴を並べる（最近の3件ではなく一覧）

## 4. B. TYP を贈る

### 4-1. 入口と相手

| 入口 | 相手 | 画面の最初の状態 |
|---|---|---|
| 歌（Version）の画面の「TYP を贈る」（主な入口） | その Version | 相手が決まった状態で量を選ぶところから |
| 人のチャンネルの「TYP を贈る」 | その人 | 同上 |
| Wallet TOP の「TYP を贈る」 | 未定 | 最近聴いた歌・フォロー中の人から選ぶ／名前で探す（★ID の手入力は無い） |

- Version 宛てと人宛ての違い（本編11章・15-1）を、確認画面で必ず言葉にする。
  - Version 宛て：「この歌に関わった人たちに届きます。分け方はこの歌の決まりに沿います」
  - 人宛て：「〇〇さんに届きます」
- Version 宛てのとき、「届く先の候補」として、その Version の参加者と、使われた貢献の作者を名前だけ出す（量・割合は出さない）。★由来（その先の世代）まで届くかは【③で確定】（Revenue Rule が決める）。確定するまでは「この歌の決まりによっては、元になった歌の作者にも届きます」とだけ書く。

### 4-2. 載せるもの（スマホ・上から順）

1. 相手のカード（歌なら題名・参加者の顔、人なら名前・顔）
2. 量を選ぶ：候補のボタン【見本：10／50／100／300】＋自由入力
   - ★候補の数・上限・下限は【③で確定】。見本の数字は仮の置き場
   - 足りないとき：「いま使える TYP が足りません（いま【見本：40】TYP）」
3. ひとこと（任意・短文）：「ありがとうのひとこと（任意）」
4. 「確認へ」ボタン

### 4-3. 贈る前の確認

- 相手（歌の題名・または人の名前）
- 量：「100 TYP」【見本】
- 贈ったあとの残り：「贈ったあと 1,140 TYP」【見本】（中央から受け取った残高から引いた見込み。確定の値は中央の記録後に出し直す）
- 届く先の言葉（4-1）
- ひとこと
- 取り消しについての1行の置き場。★取り消しの可否は【③で確定】。確定するまで、この行には何も書かない（「取り消せない」とも「取り消せる」とも先に約束しない）。文言は確定後に決める（要判断 W-4）
- どの種類の TYP から減るか（購入・付与・受け取り）は選ばせない。【③で確定：減る順】。③の決まりで種類の表示が要るなら、記録の後の詳細に出す
- ボタン：「100 TYP を贈る」【見本】

### 4-4. 贈ったあと

- 「届きました」＋相手の名前・歌の題名＋記録番号（短く）
- 「相手のウォレットに記録されました」（中央の記録が確定したときだけ出す）
- 次の一歩：「この歌をもう一度聴く」「ほかの歌にも贈る」

### 4-5. PC の並び

- 歌の画面の右側にパネルとして開く（歌を聴きながら贈れる）。確認は同じパネル内で切り替える

## 5. B の状態：二重に贈ったように見せない

完成条件「TYP を贈ると中央台帳に1回だけ記録され、送り手・受け手双方へ正しく反映される。再送しても二重反映されない」を画面側で支える。

### 5-1. 操作番号

- 確認画面を開いた時点で、その「贈る操作」に1つの操作番号を付ける。
- 「贈る」を押して通信が切れた・時間切れになったとき、画面は同じ操作番号で中央に「この操作はどうなったか」を確かめる。押し直しても同じ操作番号で送る。中央は同じ操作番号を1回として扱う（★中央の口の形はこの文書では決めない。8章の申し送り）。
- 操作番号は、確認画面を閉じて開き直すまで変えない。量や相手を変えたら新しい番号。

### 5-2. 状態ごとの見え方

| 状態 | 画面 | 押せるもの |
|---|---|---|
| 贈る前 | 確認画面 | 「贈る」「もどる」 |
| 送っている | ボタンが「贈っています…」。画面を閉じても操作は続く | なし（押せない） |
| 記録された | 4-4 の「届きました」 | 次の一歩 |
| 通信が切れた・答えが来ない | 「通信が切れました。贈れたかどうかを確かめています」。★「もう一度贈る」は出さない | 「確かめる」（同じ操作番号で照会） |
| 確かめた結果＝記録されていた | 「届いていました」（4-4 と同じ）。二重には記録されていないことを1行で書く：「1回だけ記録されています」 | 次の一歩 |
| 確かめた結果＝記録されていなかった | 「まだ届いていません。もう一度贈りますか」（同じ操作番号で送る） | 「もう一度贈る」「やめる」 |
| 中央が断った（残高不足・相手が受け取れない等） | 理由を言葉で。「いま使える TYP が足りませんでした」「この歌はいま TYP を受け付けていません」 | 「量を変える」「やめる」 |
| 確かめても分からない（中央につながらない） | 「いまは確かめられません。記録の状態は『最近贈った TYP』に出ます。二回贈ることはありません」 | 「あとで確かめる」 |

- Wallet TOP の「最近贈った TYP」には、確かめ中の操作を「確かめています」の行として1行だけ出す（2行にしない）。
- 残高は、記録が確定するまで「反映待ち」として出す。確定前に大きい数字を減らさない。

## 7. 届いた TYP の種類の見せ方

台帳では別物（③の前提）：購入した TYP／無料で付与された TYP／受け取った TYP。

### 7-1. 案

- Wallet TOP では1つの数字「いま使える TYP」に見せる（利用者が「贈る」ために知りたいのは合計のため）。
- ★ただし、③で「種類によって贈れる・贈れない」が決まった場合、1つの数字は「いま贈れる TYP」に変える（要判断 W-1）。
- 内訳は「内訳を見る」のシートで見せる：

| 種類 | 量 | できること |
|---|---|---|
| 購入した TYP | 【見本：500】TYP | 【③で確定】 |
| 付与された TYP | 【見本：300】TYP（有効期限【③で確定】） | 【③で確定】 |
| 受け取った TYP | 【見本：440】TYP | 【③で確定：円での受け取りの対象か】 |

- 贈るときに種類を選ばせない（4-3）。減る順は③。
- 届いた TYP の一覧（C）の各行に種類の小さな印を付ける（「付与」「歌を通して」「人から」）。★「購入」は自分が買ったもので、届いたものではないので C には出さない（購入の記録は【③で確定：購入履歴の置き場】）。

## 8. D. なぜ届いたか（Version Graph の説明）

### 8-1. 流れ（スマホ・上から順の4段）

えふさん確定の順に、上から1段ずつ読む形にする。

1. 出来事：「〇〇さんが『夜の散歩道 — ピアノver.』に 100 TYP を贈りました」【見本】
   - 日時・この歌の決まり（Revenue Rule）の版「この日の決まり：版3」（押すと決まりの説明。★割合の数字は③で確定するまで出さない）
2. この歌が使っている貢献：縦に並んだカード
   - 例：「詞 — 田中 蓮」「曲 — あなた」「編曲 — 伊藤 さくら」「歌唱 — 佐藤 葵」
   - ★あなたの貢献のカードだけ色を付け、他は薄く
3. あなたの貢献：「あなたの曲（『夜のピアノ』で生まれた）」
   - あなたに届いた量：「＋45 TYP」【見本】（中央の値をそのまま。★画面で割合から計算しない）
4. さらにその由来：あなたの曲が何かを基にしている／あなたの貢献が別の貢献を通して使われた場合、その道を縦の線で見せる

- 最後に：「この歌は、あなたの曲から生まれた 12 の歌のひとつです」【見本】（「自分の貢献が使われた作品」の数：追補1 22章・確定6）

### 8-2. 自分に届く道のかたち

| かたち | 見せ方 |
|---|---|
| 直接：この歌があなたの貢献をそのまま使った | 2段目のカードのうち、あなたのカードに色 |
| 由来を通して：使われた貢献が、あなたの貢献を基にしている（例：編曲C ← あなたの編曲B） | 3段目に「この歌は、あなたの貢献を直接は使っていません。使われた編曲（〇〇さん）は、あなたの編曲を基にしています」＋縦の道「編曲C → 編曲B（あなた）」 |
| 由来が何代も続く | 道の最初の2段と最後（あなた）だけを出し、間は「ほかに 3 つの貢献を通っています」で畳む。押すと全部開く。★由来は全世代たどれる（追補2 確定2）。届けるかどうかは決まり（Rule）が決めるので、画面は「道」と「届いた量」を分けて出す |
| 2つ以上の道であなたに当たる | 「この歌は 2 つの道であなたにつながっています」＋道ごとのカード。量は中央が道ごとに出すなら道ごと、まとめて出すなら合計1つ。★「1回として数える／道ごとに数える」は決まり（Rule）による（追補2 26-2）。画面はどちらでも出せる形にする |
| 由来としてはつながっているが、決まりにより届かなかった | 道は見せ、量の所に「この歌の決まりでは、この道には届きません」。★届かなかった理由を割合で説明しない |

### 8-3. 自分が複数の役割で入っているとき

- 1段目の下に「あなたはこの歌で 3 つの貢献をしています」【見本】
- 2段目で、あなたのカード（例：作詞・作曲・歌唱）すべてに色
- 3段目は、あなたの貢献ごとにカードを1枚ずつ（量も貢献ごと。中央が合計しか出さない場合は合計1つ＋「内訳はこの歌の決まりによります」）
- 一番上に合計：「あなたに届いた量 ＋120 TYP」【見本】

### 8-4. 許諾が失効した貢献・退会した人・公開を終えた歌

追補3（①ポリシー・②個別の許諾・③公開時の再検証の分離、アカウント状態と権利状態の分離、履歴つき新版）に沿う。★説明はいつも「その出来事の時点」の記録で出し、今の状態は別の1行で添える（過去を書き換えない）。

| 場面 | 見え方 |
|---|---|
| 出来事の時点では有効な許諾で使われ、今は許諾が取り消されている | カードはそのまま。下に小さく「この貢献の許可は、〇月〇日に取り消されました（この出来事より後）」。届いた量は変えない（変えるかは【③で確定】） |
| 今の再利用ポリシーが「使えない」に変わった | 表示しない（ポリシーは今後の利用の設定で、過去の出来事の説明には関係しない） |
| 参加者・作者が退会している | 名前の所を「退会したユーザー」。★その人の権利は消えていない（追補3 35-3）ので、カード自体は消さない。その人の分が保留か等は、その人の画面にしか出さない（他の人には量を見せない：要判断 W-3） |
| 参加者が匿名を選んでいる | 「参加者1名（非表示）」 |
| 歌が公開を終えている（非公開の新しい版） | 題名の所に「公開を終えた歌」。貢献のカードは出す（あなたの貢献の関係は残るため）。歌の画面へのリンクは出さない |
| 保留されている（あなたの分） | 3段目の量の所に「保留中」＋【③で確定：理由・期限・解けたときの知らせ】 |

### 8-5. 状態

| 状態 | 見え方 |
|---|---|
| 読み込み中 | 1段目だけ先に出し（出来事は届いた一覧から持ってくる）、2〜4段は灰色の枠 |
| 失敗 | 「説明を読み込めませんでした」＋「もう一度」。1段目（届いた事実）は出したまま |
| 説明が作れない（古い記録で由来の情報が足りない等） | 「この TYP がどの貢献を通して届いたかの詳しい説明は、まだ用意できていません」。届いた事実と量は出す |

### 8-6. PC の並び

- 左に4段の説明、右に森の図（この歌を中心に、使った貢献と、あなたまでの道を線で結ぶ）。図は5段以上を畳む

## 9. 利用者が迷う所・不安になる所と、画面での答え

| 迷い・不安 | 画面での答え |
|---|---|
| 贈ったのに、相手に届いたか分からない | 「届きました」は中央の記録が確定したときだけ出す。贈った記録の詳細に「相手のウォレットに記録されました」と日時 |
| 通信が切れた。二回贈ってしまったかも | 5章。「1回だけ記録されています」を必ず出す。「もう一度贈る」は、記録されていなかったと確かめた後にしか出さない |
| 残高がすぐ減らない／増えない | 「反映待ち」の行で、確定前であることを言葉で出す |
| 知らない人から TYP が届いた | 「なぜ？」で、あなたのどの貢献がどの歌で使われたかを見せる（D） |
| 知らない歌を通して届いた | D の「由来を通して」の説明。その歌へのリンク |
| なぜこの量なのか | D で「この日の決まり：版n」を見せる。割合の説明は【③で確定】の後に足す。★画面で割合を推測させない |
| 贈ると相手に自分の名前が出るのか | 確認画面に「〇〇さんには、あなたの名前とひとことが届きます」。名前を伏せて贈れるかは要判断 W-5 |
| 間違えた相手に贈った | 入口を歌・人の画面にして手入力を無くす。確認画面で相手を大きく出す。取り消しの可否は【③で確定】（W-4） |
| 歌に贈ったら誰に届くのか | 確認画面で「届く先の候補」を名前だけ出す（4-1） |
| 付与された TYP はいつまで使えるのか | 内訳シートの有効期限【③で確定】 |
| TYP は円にできるのか | 【③で確定】の後に合流する画面で答える。それまでは「TYP は、ありがとうを届けるポイントです」だけを書き、円の話を出さない |
| 退会した人の歌に贈れるのか | 歌が公開中なら贈れる。届く先の候補に「退会したユーザー」と出る。その人の分の扱いは【③で確定】 |

## 10. ③と中央の口への申し送り（この画面が中央から受け取る必要のある項目）

★口の形（API の名前・形）は決めない。項目だけ。

### 10-1. 残高

- いま使える TYP の合計（または③の決まりにより「いま贈れる TYP」）
- 種類ごとの量（購入・付与・受け取り）と、付与の有効期限
- 反映待ちの量
- 最後に確定した時刻

### 10-2. 贈る

- 贈る操作に付けた操作番号を受け取り、同じ番号を1回として扱うこと
- 操作番号での照会：記録された／記録されていない／処理中
- 断ったときの理由の種類（残高不足・相手が受け取れない・上限超え 等）
- 記録番号・確定時刻・贈った後の残高
- 量の上限・下限・候補【③で確定】
- 取り消しの可否【③で確定】
- どの種類から減ったか（③で表示が要る場合）

### 10-3. 届いた・贈った履歴

- 記録ごとに：記録番号・種類（人から直接／歌を通して／付与）・日時・量・相手（人・アカウント状態の表示名）・歌（Version と公開状態）・ひとこと・状態（確定・反映待ち・保留）
- 並びと続きの読み込み（ページの区切り）

### 10-4. なぜ届いたか（分配の明細）

- もとの出来事（誰が・どの Version に・どれだけ・いつ）
- その Version に適用された Revenue Rule の版
- その出来事の時点の Version の構成：参照した貢献ごとの作者（表示名・アカウント状態・匿名か）
- 受け取った人（自分）への量：貢献ごと・道ごと（直接／由来を通して何世代前か）・または合計のみ（③が決める）
- 由来の道（貢献どうしのつながり：全世代）
- 決まりにより届かなかった道があるか
- 保留の有無・理由・期限【③で確定】
- 許諾の履歴：出来事の時点で使った許諾（②）と、その後の取り消しの有無と日付（追補3 33章）

### 10-5. ③へ

- 種類ごとにできること（贈れるか・円の対象か・期限）
- 減る順
- 取り消しの可否
- 保留の理由・期限・解け方
- 退会・死亡・連絡不能の権利者に届く分の扱い（追補3 40章）
- 許諾が後から取り消された場合、既に届いた TYP を変えるか
- 他の受取人の量を、同じ歌の関係者に見せてよいか（W-3）
