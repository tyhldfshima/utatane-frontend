## 1. 重点画面と選んだ理由

4導線と「自分」から、次の3つの条件のどれかに当たる画面を選んだ。
- 利用者が迷う
- 取り違える
- ポイントが動く、または取り返しがつかない

| 記号 | 画面 | 導線 | 選んだ理由 |
|---|---|---|---|
| A | 歌の画面（ありがとう・参加・育てる） | ①② | 「この曲に参加する」と「新しい Version として育てる」を取り違えやすい。ありがとうのボタンの出し分け（Y4 暫定・自分も届け先）がここに集まる |
| B | 参加の入口（シート） | ① | 公開された歌への参加は、元の歌ではなく新しい制作に入る（U3）。どの歌に入るのかが伝わらないと取り違える |
| C | ありがとう：量を選ぶ | ② | ポイントが動く入口。残高の古さ・足りない・前の贈与の結果待ちで迷う |
| D | ありがとう：贈る前の確認 | ② | 取り返しがつかない（利用者は取り消せない＝T6）。確認はここで1回 |
| E | ありがとう：結果 | ② | 通信が切れたときの「結果を確認しています」で、二重に贈る心配が出る |
| F | 公開する前の確認（参加者の同意） | ③ | 「同意」と「公開」を取り違えやすい。届け方をここで初めて見る |
| G | 公開する前の確認（主催が公開する） | ③ | 取り返しがつかない（公開後は音と参加者を変えられない＝U5）。確認はここで1回 |
| H | 取引の詳細（point.ty-hld.com） | ② の後 | ポイントの記録。見せてよい物・見せない物の決まり（えふさん確定）が一番効く |
| I | 自分（管理画面 → 公開プロフィール） | 自分 | 自分だけに見える物と、ほかの人に見える物を取り違えやすい |

## 2. 全画面に共通の決まり

### 2-1 押しやすさ・迷わせない作り

- 押せる物の高さ：
  - 主ボタン・ボタン：52px
  - 小さなボタン・文字のリンク・戻る：44px 以上
  - 量の札：52px
  - 試作の全50状態で、44px 未満の押せる物は0（Playwright で測った）。
- 主ボタンは1画面に1つ。試作の全50状態で、2つ以上ある状態は0。
- 取り返しのつかない操作の前には、確認を1回だけ置く：
  - 贈る：D が確認の画面そのもの。［贈る］を押したら、そのまま送る
  - 公開する：G の確認の小窓
  - 公開に同意する：F の確認の小窓（公開前なら、同意はやめられる）
- 戻る道を必ず置く：
  - 通常のページ：左上の「戻る」
  - シート：［閉じる］［戻る］［やめる］
  - 押せない状態でも、戻る道は残す
- 押した直後の決まり：［贈る］［参加する］［公開する］は、押した直後に押せない状態へ変え、何をしているかを文字で出す（例：「贈っています」）。二重押しを防ぐ（T8）。
- 状態は色だけで伝えない。文字・形・アイコンを合わせて使う：
  - 押せないボタン：灰色の面と、理由の1行
  - 量の増減：「−300 TYP」と「あなたの TYP が減りました」
- 読み上げ：
  - 結果・状態の変化を読み上げに伝える（role=status・role=alert）。
  - 札（暫定・見本・仮の形）と「Y4 の差し込み口」の文字は、設計の印。本番の画面には出さない。

### 2-3 Y4 暫定の外し方

- 「ありがとうを贈る」の利用不可（受け取れない方がいる歌）は、1つの条件だけで出し分ける。条件は「Y4 の本番受入の前か後か」。
- 画面の中に、条件の分かれ道を別々に作らない。この条件は、A の出し分け・C の前の確かめ・D の注意の1行の3か所で同じ物を見る。
- Y4 の本番受入に PASS したら、次の2つを1回で切り替えられる作りにする：
  - A の利用不可の状態を出さなくなる。
  - D・E・H に「受け取れない方の分は送られず、あなたのポイントからも減りません」を出す。
- 条件をどこに持つかは、実装の便で決める（この設計では決めない）。
- 「自分も届け先に入っている」ための利用不可（941be1bd 3）は恒久の決まり。Y4 とは別の条件にする。

## 4. TYP のどの口の何の項目を出すか

★どの口も、利用者の端末から直接は呼ばない。
- 贈る口は UTATANE のサーバーが呼ぶ。
- 読む口は、UTATANE の画面では UTATANE のサーバーが読み、point.ty-hld.com の画面では TYポイントの画面が読む。

| 画面 | 口（中央 §5） | 使う項目 | 画面での出し方 | 出さない物 |
|---|---|---|---|---|
| C（残高） | GET /v1/point/me/wallet | balances・total・as_of | 「〇〇 TYP（〇時〇分 時点）」。total は同じ制度（typ）の中の合計だけ | 制度をまたいだ合計（凍結）・円 |
| C（量の札・上限） | ★仮の形：制度の設定を読む口（まだ無い）。見込む項目は量の札の候補・1回の上限 | 札の候補・上限 | 札・「設定の上限まで」 | — |

| E（結果を確認しています） | ★仮の形：結果を確かめる口（TYP 側の便で作る）。今の中央では、同じ鍵・同じ中身でもう一度送ると1回目の答えが返る（再送 200・replayed） | 決まり次第 | 「結果を確認しています」→ 分かったらお知らせと履歴 | — |

### H の項目ごとの扱い（PR #865 の答え）

| 項目 | 画面での扱い |
|---|---|
| type | grant＝「もらった」、transfer＝送り手なら「ありがとうを贈った」・受取人なら「ありがとうが届いた」、reversal＝「取り消し」 |
| delta | 大きく出す量。符号と「減りました」「届きました」「増えました」「戻りました」の文字を添える |
| at | 「2026年9月19日 13時06分」の形 |
| target（kind・ref） | kind が version のとき、UTATANE から題名を引いて「歌」の行に出す。ref（内部の id）は出さない |
| transfer（amount・distributed・retained） | 送り手にだけ返る。Y4 が決まるまでは画面に出さない（Y4 の差し込み口）。受取人の画面には、口が返さないので出ない |
| contributions（amount・contribution_ref・route） | 受取人の「なぜ届いた？」へ渡す（UTATANE の M14 で、どの貢献を通って届いたかを出す）。ここで他の人の分は出さない |
| sender_account_id | ★画面に出さない。UTATANE が表示名に変えて「贈った人：りんさん」と出す（受取人にだけ） |
| reverses_transaction_id・reversed_by_transaction_id | 対の取引へのリンクにだけ使う。id そのものは出さない |
| reason | 付与のときだけ返る。付与理由のデータの表示文言に変えて出す（仮の形） |
| transaction_id | 画面に出さない。問い合わせるときの内部の引き継ぎにだけ使う（要判断：問い合わせのときに利用者へ見せる番号） |
