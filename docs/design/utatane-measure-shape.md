# 計測の「形だけ」（正本 §4 のループ8段を、画面の操作点に置く）

★えふさん確定（1文字も変えない）：

> 計測の「形だけ」：正本 §4 のループ8段を、送り先を決めない送り口で画面の操作点に置く（名前・基盤・保存期間は固定しない）。

- 正本：[utatane-completion-criteria.md](utatane-completion-criteria.md) §4（計測の条件）
- ★**この文書と実装がずれていないことは `app/ui/measure.test.ts` が見張ります。**
  表の「画面」欄を書き換えると、試験が落ちます。
- ★**決めていない物**：イベント名・分析基盤・保存期間・送り先。正本の「今ここで固定する必要はありません」のとおりです。
- ★**この便で作っていない物**：通知（確定18）・リリースゲートの文面・TYポイント側。本番へも反映していません（メンテナンス表示のまま）。

## 1. 8段 × 画面の有無（対応表）

成長ループ（正本 §4）：**種 → 参加 → Contribution → Version → 公開 → TYP → 次の創作**

| # | 段 | 画面 | 操作点（画面と、その操作を終えた住所） | 置いた場所 |
|---|---|---|---|---|
| M-1 | 種 | まだ画面が無い | ＋つくる（`/ui/create`）に始め方は並ぶが、**進める始め方が「今ある歌から育てる」しか無い**（他の3つは「準備中」）。育てるは M-8 に数えるので、種を作り終える操作点はまだ無い | — |
| M-2 | 参加 | あり | 参加する（`/ui/songs/[id]/join?step=submit`）＝**何で参加するかが決まり、送る画面に入った時点** | `app/ui/songs/[id]/join/page.tsx` |
| M-3 | Contribution | あり | 参加する（`/ui/songs/[id]/join?step=sent`）＝**送った時点** | `app/ui/songs/[id]/join/page.tsx` |
| M-4 | Contribution（採用） | まだ画面が無い | 主催が「送られた物をこの歌に入れる」操作。**主催から見た制作中の歌の画面がこのリポに無い**（`app/ui/drafts/[id]` は参加した人から見た形。`app/ui/drafts/[id]/publish/page.tsx` の注記が根拠）。`/ui/inbox` の「送られた歌の確認」も、いま中身が空 | — |
| M-5 | Version | まだ画面が無い | Contribution が集まって Version になる操作。M-4 と同じ主催の画面に属し、まだ無い。★育てて作る下書きは M-8 に数える | — |
| M-6 | 公開 | あり | 公開する前の確認（`/ui/drafts/[id]/publish?done=1`）＝**公開が済んだ時点** | `app/ui/drafts/[id]/publish/page.tsx` |
| M-7 | TYP | あり | ありがとうを贈る（`/ui/songs/[id]/thanks?step=result`）＝**届いた時点**。届かなかったとき（`r=failed`・`r=paused`）と、結果が分からないとき（`r=checking`）は鳴らさない | `app/ui/songs/[id]/thanks/page.tsx` |
| M-8 | 次の創作 | あり | 育てる →（`/ui/drafts/new?from=…&take=…`）＝**元の歌から受け継いだ新しい Version の下書きができた時点**。受け継ぐ物が0件のときは Version の派生ではないので鳴らさない | `app/ui/drafts/[id]/page.tsx` |

★**画面が在るのは5段、まだ無いのは3段（M-1・M-4・M-5）です。**
無い3段は、このリポに操作点そのものが無いので、置く場所がありません（無理に鳴らす場所を作っていません）。

### なぜ M-2 と M-3 を分けたか

正本 §4 が求めているのは「**ループのどこで止まったか**が分かること」です。
参加の流れは「役割を選ぶ → 送る」の2手なので、**参加を決めたのに送らなかった**という止まり方があります。
両方を「送った時点」にまとめると、この止まり方が測れません。だから2つの操作点に分けました。

## 2. 送り口（呼ばれても外へ送らない形）

| 物 | 場所 | 中身 |
|---|---|---|
| 送り口の形 | `lib/measure/port.ts` | `MeasureSink.mark(stage)`。引数は**段の番号ひとつだけ**（M-1〜M-8） |
| 送り口を選ぶ1か所 | `lib/measure/index.ts` | 既定は `noopSink`＝**何もしない**。`setMeasureSink()` で差し替えられる |

- ★**外へ1バイトも送りません。** 通信も保存も記録もしません。試験が、操作点を全部描いても通信が1回も起きないことを実測しています。
- ★**名前を決めていません。** 渡すのは正本 §4 の表の番号（M-1〜M-8）だけです。
  `seed_created` のような概念の例は、`lib/measure` に1つも書いていません（試験が見張っています）。
- ★**誰が・いつ・どの端末かも渡していません。** 渡す物を決めるのは、送り先を決める便です。
- ★**後から差し替えられます。** 読み口（`lib/ui-data`）と同じ作りで、差し替えるのは `lib/measure/index.ts` の1行だけ。画面は1枚も書き直しません。

## 4. 次に決めることと、この形との関係

| 決めること | いつ | この形をどう直すか |
|---|---|---|
| イベント名 | 送り先を決める便 | 段の番号に名前を対応させる表を送り口の中に置く。**画面は触らない** |
| 分析基盤・保存期間 | 同上 | `lib/measure/index.ts` の1行を差し替える。**画面は触らない** |
| M-1・M-4・M-5 の画面 | それぞれの画面を作る便 | 画面ができたら、その操作点で `measure().mark(...)` を1行呼び、この表を「あり」に直す |
