### TYポイント側（★担当外・参照のみ）

原文：「残高を見る → TYPを使う → 最終確認 → 完了 → 履歴を見る → UTATANEへ戻る を一周させます。」

UI受入条件（原文）：

- TYポイント共通基盤とTYPを混同しない
- 交換不能Programを合算して誤認させない
- 処理中・成功・失敗・結果確認中を区別する
- 円建て報酬とTYPを混ぜない

★これは `point.ty-hld.com`（TYポイント）の画面の条件です。**このリポでは確かめません。** 一周の最後の「UTATANEへ戻る」の戻り先だけが、このリポに関わります。

## 4. 計測の条件（MVP開始時から測れなければならない物）

原文：「計測は『数字』だけでなく、UTATANEの成長ループを測る」

成長ループ（原文）：

> 種 → 参加 → Contribution → Version → 公開 → TYP → 次の創作

原文：「のどこで止まったかが分かるイベント設計にしてください。」

概念の例（原文のまま・★名前は固定ではない）：

| # | 段 | 概念の例 |
|---|---|---|
| M-1 | 種 | `seed_created` |
| M-2 | 参加 | `participation_requested` |
| M-3 | Contribution | `contribution_submitted` |
| M-4 | Contribution（採用） | `contribution_accepted` |
| M-5 | Version | `version_created` |
| M-6 | 公開 | `version_published` |
| M-7 | TYP | `typ_sent` |
| M-8 | 次の創作 | `derived_version_created` |

- ★原文：「イベント名・分析基盤・保存期間を今ここで固定する必要はありません。」
  決まっているのは **「MVP開始時から、上のループのどこで止まったかを測れること」** だけです。実装方式は別に決めます。
- ★**いま**：このリポに計測の仕組みはまだありません（見本データで動いているため、測る対象がまだ無い）。
- ★単純な PV・いいね数だけを測っても、この条件は満たしません。

## 5. この文書が「完成」と呼ばない物

- ★**画面が全部あっても、完成ではありません**（§3：初見の人が一周できること）。
- ★**main に合流しても、本番で使えるとは限りません**。本番への反映とメンテナンス表示を外す判断は人の手番で、§2 の5つが揃う前には外しません。
- ★**いまの画面の中身は、すべて見本データです**（`lib/ui-data` の読み口が `sampleSource` のまま）。本物のデータにつながるまでは、§3 の人の受入も §4 の計測も始められません。
